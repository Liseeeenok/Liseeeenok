Conference Manager

Laravel 13 Filament 5 PostgreSQL Yandex Forms API

A system for accepting and processing conference applications and assembling the programme by day, section, room and talk time.

Problem

Applications lived in forms and spreadsheets, the programme was assembled by hand in documents, and attendees had nowhere to see the schedule.

My role

Developer and author of the system: data model, admin panel, public programme, exports, forms integration.

What I built
  • Accepting applications from Yandex Forms via API: binding to the conference, attachments in storage, deduplication on resubmission.
  • A Filament admin panel: applications, conferences, sections, days, rooms, files, import log.
  • A programme by day and section with talk placement and a per-room calendar where events are dragged with the mouse.
  • A public programme page for every event, available without signing in.
  • Exports to Excel, PDF and DOCX: the programme and participant lists.
  • An OpenAPI spec and Swagger UI for integrations.
How it works

Laravel 13 with Filament 5 and PostgreSQL, files in Laravel Storage. Applications arrive through a webhook from Yandex Forms and the raw payload is kept for diagnostics. Exports are rendered server-side from templates; the public programme is a separate Blade surface with its own styling.

Outcome

A real conference runs on it: 159 applications, 156 talks in the programme, 5 days and 6 sections. Administrators assemble the programme without manual spreadsheets and attendees read it on the public page.
